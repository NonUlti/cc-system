# CLAUDE.md 자동 생성 에이전트

대상 프로젝트를 분석하여 루트 및 주요 하위 디렉토리에 CLAUDE.md 파일을 자동 생성하라.
아래 단계를 순서대로 수행하라.

---

## 0단계: 대상 프로젝트 경로 입력

**이 단계는 반드시 가장 먼저 수행하라. 사용자가 경로를 확정하기 전까지 다음 단계로 넘어가지 마라.**

사용자에게 바로 프로젝트 경로를 직접 입력받아라. 현재 디렉토리를 확인하거나 추천하지 마라.

다음과 같이 사용자에게 질문하라:
"CLAUDE.md를 생성할 프로젝트의 절대 경로를 입력해주세요. (예: /Users/username/projects/my-app)"

- 사용자가 경로를 입력하면, 해당 경로가 실제로 존재하는 디렉토리인지 확인하라.
- 경로가 존재하지 않으면 다시 입력받아라.
- 이후 모든 단계에서 사용자가 지정한 경로를 프로젝트 루트로 사용하라.

## 1단계: 프로젝트 구조 파악

- `find <프로젝트경로> -maxdepth 4 -type f | head -300` 으로 전체 파일 목록을 확인하라.
- `ls -la <프로젝트경로>` 로 루트 디렉토리 내용을 확인하라.
- 기존 CLAUDE.md 파일이 있는지 `find <프로젝트경로> -name "CLAUDE.md" -maxdepth 4` 로 확인하라.
- 결과를 기억하고 다음 단계로 넘어가라.

## 2단계: 기술 스택 및 설정 파악

다음 파일들이 존재하면 읽어서 기술 스택, 빌드/테스트/린트 명령어, 코드 스타일 규칙을 파악하라:

- **패키지 매니저/의존성**: `package.json`, `pyproject.toml`, `Cargo.toml`, `go.mod`, `Gemfile`, `pom.xml`, `build.gradle`, `requirements.txt`, `composer.json`
- **린트/포맷터 설정**: `.eslintrc*`, `.prettierrc*`, `biome.json`, `.flake8`, `setup.cfg`, `rustfmt.toml`, `.editorconfig`, `ruff.toml`, `pyproject.toml`의 `[tool.black]`/`[tool.ruff]` 섹션
- **빌드 설정**: `Makefile`, `Dockerfile`, `docker-compose.yml`, `tsconfig.json`, `vite.config.*`, `webpack.config.*`, `next.config.*`
- **CI/CD**: `.github/workflows/*.yml`, `.gitlab-ci.yml`, `Jenkinsfile`
- **기타**: `README.md`, `CONTRIBUTING.md`

## 3단계: 루트 CLAUDE.md 생성

**기존 CLAUDE.md가 루트에 이미 존재하면**: 덮어쓰지 말고 사용자에게 "루트 CLAUDE.md가 이미 존재합니다. 덮어쓰기/병합/건너뛰기 중 선택해주세요"라고 물어보라.

기존 파일이 없다면, 다음 구조로 루트 `CLAUDE.md`를 생성하라:

```markdown
# 프로젝트명

프로젝트에 대한 한두 줄 개요.

## 기술 스택

- 언어: ...
- 프레임워크: ...
- 주요 라이브러리: ...

## 빌드/실행 명령어

- 설치: `npm install` / `pip install -e .` 등
- 개발 서버: ...
- 빌드: ...
- 테스트: `npm test` / `pytest` 등 (단일 파일 테스트 명령어도 포함)
- 린트: `npm run lint` / `ruff check .` 등
- 커밋 메시지 형식 (컨벤션이 있는 경우)

## 아키텍처 개요

프로젝트의 전체 구조를 간략히 설명.

## 디렉토리 구조

주요 디렉토리와 역할을 설명.

## 코드 스타일

- 포맷터/린터 설정에서 추출한 핵심 규칙
- 네이밍 컨벤션
- import 순서 등

## 주의사항

- 코드만 봐서는 알기 어려운 암묵적 규칙이나 팀 관습
- 자주 실수하기 쉬운 부분
- "이렇게 보이지만 실제로는 이런 이유로 이렇게 동작한다" 같은 것들
- 특이한 설정이나 우회 방법이 있는 경우

## 환경 요구사항

- 필요한 환경변수 목록 (이름만, 실제 값은 절대 포함하지 않음)
- 필요한 외부 도구/의존성 (예: Docker, Redis, PostgreSQL 등)
```

실제 프로젝트에서 파악한 내용으로 채워라. 존재하지 않거나 해당 없는 섹션은 제거하라.

## 4단계: 하위 디렉토리 CLAUDE.md 생성

### 생성 기준 (모두 만족해야 함)

1. **독립적 역할이 명확한 디렉토리**: `src/`, `lib/`, `api/`, `app/`, `components/`, `pages/`, `routes/`, `services/`, `utils/`, `hooks/`, `models/`, `controllers/`, `middleware/`, `tests/`, `scripts/`, `packages/*` 등
2. **소스 파일이 3개 이상** 있는 디렉토리
3. **depth 3 이하** (루트 기준, 예: `src/components/`는 OK, `src/components/ui/buttons/`는 너무 깊음)

### 생성하지 않는 경우

- `node_modules/`, `.git/`, `dist/`, `build/`, `__pycache__/`, `.next/`, `target/`, `vendor/` 등 생성물/의존성 디렉토리
- 설정 파일만 있는 디렉토리
- 파일이 2개 이하인 디렉토리
- monorepo의 경우 각 패키지 루트에는 생성하되 그 안의 하위는 선별적으로

### 각 하위 CLAUDE.md 내용

```markdown
# 디렉토리명/

이 디렉토리의 역할과 책임을 한두 줄로 설명.

## 파일 구조

- 파일 네이밍 규칙 (예: `*.controller.ts`, `use*.ts` 등)
- 주요 파일 설명

## 패턴

이 디렉토리에서 사용되는 주요 패턴 설명.
(예: 컴포넌트 구조, API 라우팅 패턴, 훅 작성 패턴 등)

## 관련 디렉토리

- 이 디렉토리와 관련된 다른 디렉토리들과의 관계
```

실제로 파악한 내용만 작성하라. 추측하지 말고, 코드를 실제로 읽고 파악하라. 해당 없는 섹션은 제거하라.

**기존 CLAUDE.md가 하위 디렉토리에 이미 존재하면**: 덮어쓰지 말고 사용자에게 해당 경로를 알려주며 "덮어쓰기/병합/건너뛰기 중 선택해주세요"라고 물어보라.

## 5단계: 결과 보고

작업이 완료되면 다음을 출력하라:

1. 생성된 CLAUDE.md 파일 목록 (경로)
2. 건너뛴 파일 목록 (이미 존재하여 건너뛴 경우)
3. 각 파일의 핵심 내용 요약 (한 줄씩)

---

## 중요 규칙

- **실제 코드를 읽어라**: 추측하지 말고 실제 파일을 읽고 분석하라.
- **간결하게 작성하라**: CLAUDE.md는 AI가 빠르게 컨텍스트를 파악하기 위한 것이다. 불필요하게 길게 쓰지 마라.
- **덮어쓰지 마라**: 기존 CLAUDE.md가 있으면 반드시 사용자에게 확인하라.
- **프로젝트에 맞게 조정하라**: 위 템플릿은 가이드일 뿐이다. 프로젝트 특성에 맞게 섹션을 추가/제거하라.

## 작성 원칙

> CLAUDE.md는 **"새로 합류한 시니어 개발자에게 첫날 알려줄 것들"**이라고 생각하라.

### 포함해야 하는 것

- **코드만 봐서는 알 수 없는 것**: 암묵적 규칙, 팀 관습, 비자명한 설계 결정 이유
- **실행 가능한 정보**: 읽고 바로 행동할 수 있는 명령어와 규칙
- **함정과 주의사항**: 자주 실수하기 쉬운 부분, 비직관적인 동작

### 절대 포함하지 말아야 하는 것

- **비밀 정보**: API 키, 토큰, 비밀번호, `.env` 파일의 실제 값, DB 접속 정보. 환경변수는 **이름만** 기재하라.
- **뻔한 내용**: 코드를 읽으면 바로 알 수 있는 것, 프레임워크 공식 문서에 있는 일반적인 사용법, 언어 기본 문법
- **금방 낡는 정보**: 이미 해결된 임시 해결책, 완료된 마이그레이션 계획, 더 이상 유효하지 않은 TODO
- **과도하게 긴 설명**: 상세한 문서는 별도 파일로 분리하고 링크만 기재하라. CLAUDE.md는 매 대화마다 컨텍스트에 로드된다.
- **개인 환경 특화 내용**: 특정 개발자의 로컬 경로, 개인 IDE 설정, 특정 OS에만 해당하는 설정

### 파일 생성 규칙

- 생성하거나 수정하는 파일은 반드시 trailing newline(`\n`)으로 끝나야 한다. Write 도구 사용 시 content 마지막에 개행을 포함한다.
